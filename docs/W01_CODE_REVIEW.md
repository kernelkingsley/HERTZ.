## Findings

1. **[P1] An old acknowledgment destroys newer saved draft edits.** `Tools/HertzStudio/api/src/store.mjs:283-288` updates the current draft unconditionally when any queued version succeeds. Reproduction with an isolated copy of the real store: enqueue v1 at X=0, save v2 at X=10, then acknowledge v1 with its scene export. The v2 document becomes X=0 and `Applied to Unity`, without a version increment. Bind acknowledgments to `command.draftVersion`; preserve newer draft content/status and reconcile its base explicitly. Regression check: edit a draft while an earlier version is queued/applying, then deliver its acknowledgment.

2. **[P1] Revision checks miss actual Unity edits.** `Assets/Editor/HertzStudio/HertzStudioHttpBridge.cs:380-388` reads a manually maintained EditorPrefs integer. Only bridge apply/undo/save advance it; Inspector changes, ordinary Unity undo, scripts, and external scene changes are not observed. A draft exported before a Unity edit therefore passes the same revision check and reapplies all its old positions, overwriting that edit. Use a project/scene-scoped revision or content fingerprint that tracks authoritative scene changes, including reopen/reload and normal editing. Verify a local transform change between export and apply produces a conflict without mutation.

3. **[P1] Retrying a successfully applied command reports conflict after a lost acknowledgment.** `Assets/Editor/HertzStudio/HertzStudioHttpBridge.cs:274-284` checks the old base revision before duplicate detection. The first apply increments the revision; a retry necessarily fails this check before reaching the duplicate branch. `_lastAppliedRequestId` is also one volatile value, lost on domain reload. Persist/reconcile request results against their payload and scene identity, and return the original result for a valid retry before testing the already-consumed base revision. Test lost HTTP response/acknowledgment and restart/reload without a second mutation or false conflict.

4. **[P1] First-time pairing leaves the level editor empty.** `Tools/HertzStudio/api/src/store.mjs:365-371` discards `snapshot.objects`; it stores only revision/path/time. The connector imports that snapshot once (`connector/src/connector.mjs:102-113`), while the browser only loads an existing draft and has no create-from-scene action (`web/src/pages/LevelEditor.jsx:19-30`). On a clean store, pairing/export produces zero drafts and no persisted scene object list. The proof script masks this by creating a draft through its own API call. Persist the exported scene representation and expose a supported way to create/open its draft without overwriting existing disconnected drafts. Verify clean startup -> pair -> edit through the UI without running the proof script.

5. **[P1] Invalid batches partially mutate Unity while reporting failure.** `Assets/Editor/HertzStudio/HertzStudioHttpBridge.cs:296-307` resolves and moves objects one at a time. If a later ID is missing, earlier transforms have already moved, but the method returns 400 before updating the revision/result. Validate the entire batch before mutation, check every object belongs to the intended scene/project, reject malformed/non-finite transforms, and roll back any mutation-time failure. Test a valid first edit followed by an invalid ID and verify no changes, no revision inconsistency, and no leaked undo group.

6. **[P1] Local bridge mutations bypass connector authentication.** `Assets/Editor/HertzStudio/HertzStudioHttpBridge.cs:157-173` accepts apply, undo, and save from any caller that can reach port 8791. It checks neither a local connector credential nor the request origin/content type; the API pairing token is never checked at this boundary. Any unrelated local process can invoke scene mutations without Studio sign-in or pairing, including global Undo. Require an authenticated local transport or credential, bound to the intended project; validate request method/origin/schema and limits before dispatch. Verify unpaired requests cannot mutate or save, and paired connector requests still work. Loopback binding alone is not caller authentication.

7. **[P1] The proof script passes failed/conflicting workflows.** `Tools/HertzStudio/scripts/proof-drafts.mjs:141-143` accepts `failed`/`conflict` as terminal, then line 207 records them and line 215 reports success. An isolated HTTP fixture returning a terminal connector conflict made the actual script exit 0 with `report.ok=true` and no apply/undo/save calls. The direct fallback also accepts HTTP 409 as success (line 162), bypasses connector acknowledgment, and labels another export as reopen (line 186); it never closes/reopens the scene. Require successful paired connector execution, persisted acknowledgment, verified transforms, undo, explicit save, and an actual safe close/reopen. Report unavailable integration checks as pending, not full success. Keep fixtures separate from genuine Unity evidence and restrict any mutation proof to a dedicated test scene before it starts.

8. **[P2] Apply continues after a failed draft save.** `Tools/HertzStudio/web/src/pages/LevelEditor.jsx:67-68` catches save errors without rethrowing or returning a failure result. `queueApply` awaits this function at line 76 and then queues anyway at lines 78-80. A version conflict, validation error, or failed save can therefore queue older server content after the UI edit was not saved. Return the saved version or propagate the error; bind apply to that exact version and abort on any failed save. Verify a 409/failed PUT sends no apply POST and shows the save error.

9. **[P2] Conflict results leave drafts stuck Applying.** `Tools/HertzStudio/api/src/store.mjs:273-276` changes the command status but never the associated draft status, unlike success/failure branches. Isolated reproduction: enqueue, mark applying, acknowledge conflict -> command `conflict`, draft `applying`. Update the matching draft version's conflict state and details while preserving newer saved edits. Verify the browser shows an actionable conflict rather than indefinite Applying.

10. **[P2] A stopped connector stays Connected indefinitely.** `Tools/HertzStudio/api/src/store.mjs:355-361` persists the last `unityConnected` value; project/connections reads never expire it. Setting the stored last heartbeat to the year 2000 still returns `unityConnected=true`. Closing the process or powering off the PC cannot send an offline poll. Compute freshness from a bounded heartbeat timeout and refresh visible status; retain the last sync separately. Verify stopping the connector changes the UI to disconnected/stale after the timeout, while drafts remain editable.
