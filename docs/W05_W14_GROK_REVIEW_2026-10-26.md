## W06 — capture path and proof are still incomplete

- `HertzAnalyticsCapture.OnDisable` calls `CompleteAndStage(false)` without containing file-system exceptions. A lifecycle callback can fail during shutdown/domain changes.
- Every session stages to one `w06-pending-capture.json`. A later session overwrites the pending item. Archived copies do not form a connector-visible queue, so multiple offline sessions are not reliably uploaded exactly once.
- A staging failure leaves `_captureWritten` false, but the next `BeginSession` clears in-memory state and paths. Retry state is not durable.
- The player path first derives a project-relative `Tools/HertzStudio/data` path from `Application.dataPath`; on a built player, especially Quest, this is not a reliable connector transfer location.
- Dynamic target lifecycle subscription/deduplication is a good partial correction.
- `HertzStudioAnalyticsProof` invokes `RaiseShotAcceptedForProof` directly. That bypasses the actual fire/frequency gate and hit path, so it cannot prove accepted firing behavior.
- Its frame-sample loop records no samples. It checks only broad event strings rather than the required separate shot/hit/miss/defeat/frequency counts, duration, completion reason, weapon usage, frame-time data, and dashboard filter results.
- The re-enable assertion `capture.IsSessionOpen || capture.EventCount >= 0` is effectively always true.

The W06 aggregate correctly remains pending and rejects fixture-only completion.

## W07 — hash check improved, stale and idempotency cases remain

Exact acknowledgement hash matching, missing/mismatched hash rejection, unknown request rejection, and same-job applied retry handling are useful corrections. The focused sound tests pass.

Two required cases remain:

- Stale acknowledgement detection considers only newer `pending_unity` or `applying` jobs. A late acknowledgement for an older job can still overwrite global sound sync/mapping after the newer job is already `applied`.
- `enqueueSoundSync(requestId)` returns the existing job for a reused request ID without verifying that the new canonical payload/hash is identical. A changed payload under the same request ID must return a conflict.

Also align the HTTP route with the store behavior: `acknowledgeSoundSync` throws for an unknown request, so the route's null/404 branch is unreachable unless the error is explicitly mapped. Add regressions for newer-terminal-job stale acknowledgements and duplicate request IDs with changed payloads. Live connector → Unity → runtime playback remains pending.

## W08 — undo journal is partial and currently uncompilable

The operation journal is a better direction than global undo, but it is not transactional yet:

- The scene mutation and journal entry can survive if scene save/revision work later fails; the catch path does not restore the prior state.
- Undo restores references but does not clean up generated material or `TerrainLayer` assets created solely by the failed/undone operation.
- HDRI state stores the prior skybox path, ambient mode, and realtime-GI flag, but the generated sky material is reused and mutated. Restoring the same asset path cannot restore its previous texture/exposure/rotation values.
- Compiler errors prevent any live floor/wall/Terrain/HDRI proof.

Require atomic apply-or-rollback behavior, complete HDRI property snapshots, generated-asset ownership/cleanup rules, revision checks, save/reopen verification, and live dedicated-scene proof.
