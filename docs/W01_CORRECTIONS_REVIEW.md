## Findings

1. **[P1] Unsupported enum member prevents Unity from compiling.** `Assets/Editor/HertzStudio/HertzStudioHttpBridge.cs:162` references `ObjectChangeKind.UpdateScene`. The user's screenshot and `%LOCALAPPDATA%/Unity/Editor/Editor.log` both show CS0117 at `(162,46)` and Safe Mode. The installed Unity **6000.0.85f1** API documentation at `C:\Program Files\Unity\Hub\Editor\6000.0.85f1\Editor\Data\Managed\UnityEditor.xml:41386` lists **`ObjectChangeKind.ChangeScene`**, not `UpdateScene`. Correct against the installed API and verify Unity recompiles cleanly. This is an actual compiler error, not merely an unfocused Editor or a delayed domain reload. Do not treat a web build as Unity compilation, and do not ask Kingsley to bypass Safe Mode while the error remains.

2. **[P1] Malformed transform values still become valid, unintended positions.** `HertzStudioHttpBridge.cs:947-954` relies on `ReadFloat` at lines 1137-1176. That parser scans beyond the requested value for the next digit and defaults missing/unparseable fields to zero. For `{"x":"oops","y":7,"z":9}` it reads X=7; null X also becomes 7; missing X becomes 0. These results pass the new `IsFinite` validation. The API accepts these objects without numeric schema checks, so invalid input can still move objects instead of failing the entire batch. Use typed JSON deserialization plus required numeric fields and finite/range checks at both boundaries. Verify malformed/missing/null axes return an error and leave all transforms unchanged.

3. **[P1] Proof execution can modify and save the user's working scene.** `Tools/HertzStudio/scripts/proof-drafts.mjs:75-85` adopts whichever scene is exported. It later applies a move to the first exported object, invokes global Undo, saves, and reopens that scene without requiring the dedicated test scene or a disposable copy. The default fixture path does not protect the live-bridge branch. Add a scene/project guard before any mutating API request or queue enqueue, and restore test state afterward. Verify running the proof while SampleScene or another working scene is active refuses without changes. Do not rerun this script against the live Editor until that guard exists.

4. **[P1] Bridge-generated change events can invalidate the revision just acknowledged.** `HertzStudioHttpBridge.cs:138-165` unconditionally bumps the active scene revision for a matching published change event. Bridge apply records undoable transforms, resets `_suppressRevisionBump` before returning, and stores the fingerprint/revision at lines 571-575. A subsequently published event for that same change reaches the handler after suppression has ended and advances the revision again despite unchanged content. The draft retains the earlier acknowledged base, making the next apply falsely conflict. Compare fingerprints before bumping for published events and account for bridge-originated changes across the deferred event boundary. Verify two consecutive browser applies succeed with no intervening Unity edits, while an actual Inspector edit causes a conflict. This is a code-path finding; live reproduction is blocked by R1.

5. **[P2] Unity is reported Connected even when the connector explicitly says it is offline.** `Tools/HertzStudio/api/src/store.mjs:400-405` returns `unityConnected: fresh`, ignoring `store.project.unityConnected`. A still-running connector in Safe Mode continues polling with `unityReachable=0`; every poll is fresh, so the website reports Unity connected indefinitely. Isolated reproduction: `touchConnector(false, 0)` -> stored reachability false, public reachability true. Combine heartbeat freshness with the last observed reachability; distinguish a running connector from a reachable Unity bridge. The UI also needs status refresh rather than only a mount-time fetch. Test bridge offline with connector still polling as well as connector process exit.

6. **[P2] The new proof's lost-ack test uses a stale base after its own undo/save.** `Tools/HertzStudio/scripts/proof-drafts.mjs:269-287` takes the base from `draftNow.data.baseUnityRevision`. The preceding undo/save/reopen calls go directly to the bridge and never update that draft's base. Apply acknowledgment sets base R; undo and save advance live Unity to at least R+2; the first retry-test request therefore conflicts before a retry is exercised. A revision-consistent isolated fixture reproduced exit 1 with `Stale base 1, current 3`. Capture the live revision after those operations and use it for both identical requests; verify one mutation and the same original successful result on retry/reload.

7. **[P2] The proof can still pass without applying or restoring any transform.** `proof-drafts.mjs:209-211` only checks that an object exists, falls back to a different object if the intended ID is missing, then labels its position verified without comparing it with the requested value. Undo/save/reopen responses are also not followed by assertions of actual restored/persisted state. An isolated fixture that always exported X=0 while the requested draft moved to X=6.25 produced `ok=true`, `unityIntegration=passed`, and exit 0. Assert exact stable object identity and expected transforms, verify undo/restoration and state after reopen, and fail on any no-op response. Keep the synthetic old-command acknowledgment at lines 151-168 in isolated API regressions; injecting success without a Unity mutation into the real live queue is not evidence of connector correctness and can race its real consumer.

8. **[P2] Apply still does not bind the version just saved in the browser.** `Tools/HertzStudio/web/src/pages/LevelEditor.jsx:99-105` now correctly aborts on save errors, but sends only `requestId` after saving. `api/src/server.mjs:162-165` and `api/src/store.mjs:205-221` enqueue whichever draft version exists when the POST arrives. If another tab saves between the PUT and POST, the first tab silently applies that other version. Send the saved version and require it to match in enqueue, returning 409 before queueing on mismatch. Verify the interleaving with two clients.
