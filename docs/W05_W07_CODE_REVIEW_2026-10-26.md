## Findings

### W06 — high: gameplay captures are never completed and staged for upload

`HertzAnalyticsCapture` records the required events and exposes `WriteCaptureFile()`, but no runtime path calls that method. `OnDisable()` ends the session and then the component is disabled without writing or staging the capture. The only call to `StagePendingAnalyticsCaptureFile` is the editor proof generator. A real playtest therefore cannot reach the connector through the implemented lifecycle.

Required correction: add a bounded, explicit capture-completion path that ends the session, writes the file, and stages it for connector upload. Make repeated completion/disable idempotent and preserve incomplete-session semantics.

### W06 — high: the aggregate proof is synthetic, not a recorded playtest

`proof-w06-aggregate.mjs` consumes `w06-sample-capture.json`. That file is authored by `HertzStudioAnalyticsProof.ExportSampleCapture`, which constructs event JSON directly; it is not exported from a played `HertzAnalyticsCapture` session. The script also reuses any existing sample indefinitely and has no source/build identity or freshness check. It proves server aggregation and dedupe, but not the W06 acceptance criterion that a recorded playtest populates correct metrics.

Required correction: create a Unity runtime proof that drives the real frequency/weapon/target event producers through `HertzAnalyticsCapture`, completes and stages the capture, imports it through the connector/API path, and validates traceable aggregates. Reject stale or fallback fixtures as completion evidence.

### W06 — medium: dynamically spawned targets are not subscribed

`HertzAnalyticsCapture.Subscribe()` enumerates targets once in `OnEnable`. Targets spawned later cannot emit `enemy_defeat` into the capture. Add registration/lifecycle handling or subscribe through a stable global event source.

### W07 — high: mismatched Unity payload hashes can be marked applied

`acknowledgeSoundSync()` accepts `ok: true` regardless of whether `observedPayloadHash` matches the queued job hash, then records the job hash as applied. This permits stale or wrong Unity state to be reported as synchronized.

Required correction: require an exact observed hash match for successful acknowledgements, fail closed on missing/mismatched hashes, and add retry/idempotency/conflict tests.

### W07 — high: milestone runtime proof is still pending

The fresh W07 aggregate honestly reports 11/13 and pending connector delivery, Unity application, runtime playback, and manual verification. `w07-sound-runtime-proof.json` has source `pending_unity_unavailable` and 0/0 checks. Run the live connector → Unity sync and verify an assigned Kenney clip plays from the intended weapon event/emitter plus the floor mapping in `HertzSoundTest`/`HertzWeaponTest`.

### W05 — low: Unity proofs can be reused indefinitely

Fresh `regress:w05` passed, but its aggregate reused Unity artifacts stamped 24 October without validating source/build identity or freshness. This does not block W05 because the reviewed runtime, safety, persistence, dependency, and behavior paths match the acceptance criteria, but future proof hardening should bind artifacts to current source/build identity.
